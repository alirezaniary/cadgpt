# DEC-0015 — We build the codification harness; the ratifier is not yet named

**Status:** DECIDED — deferred by the stakeholder; real corpus is the last work, not the first
**Date:** 2026-08-30
**Decided by:** Stakeholder (harness), unresolved (ratifier)
**Affects:** `codification`, O2, the entire corpus

## Problem
`prd.md` §8 step 2: a draft is not a record until a **named** domain expert ratifies it, and
that person is the attributable author of the interpretation. The corpus is the product's
actual asset, and it is gated on a person who does not currently exist in this project.

## Constraints
- Stakeholder direction: *"you need to create an api llm service that translates the rules into
  consumable rules for the system … you are not the translator, you just build the harness."*
  Building the harness is settled. Producing corpus content is not our work.
- `prd.md` §8: *"The step is never skipped and never automated away, and the bottleneck it
  introduces is the point of it."*
- I5 and `prd.md` §5.7: a finding citing a clause asserts that the clause says something. If
  that interpretation is wrong, the assertion is made under the product's name, and the defence
  is a named ratifier and a stored source quote.
- `prd.md` §12: this reopens *"never in shape. If ratification binds, the answer is better
  proposals and better review tooling, not removing the ratifier."*

## Decided
We build the codification service in full: extract → ratify → classify → compile → fixture, the
quote linter, and the ratification review tooling. It is **artifact-mediated** — it emits files
into version control and the engine consumes committed records. It is never in the request path.

A **draft** has no ratifier and **cannot compile**. The state transition to `ratified` requires
a name, not a flag. This is enforced in the schema and by the compiler's refusal, so an
unratified corpus is structurally unable to ship.

## Resolved — corpus content is deliberately last
Stakeholder direction, 2026-08-30: *"you don't need exact values to complete the harness; the
translation of real rules is the last thing I do — we can download samples from the internet
and go on."*

This closes the question rather than deferring it vaguely. The whole pipeline — harness,
compiler, resolver, evaluator, findings, report — is built and proven against **sample and
synthetic packs**, and real regulatory content is loaded at the end.

Three sources cover the build entirely, with no real clause required:
- buildingSMART's published sample IDS files and the Regulatory Information Requirements
  localisation outline (DEC-0019).
- **Synthetic packs generated by us**, which are strictly better for testing than real ones: a
  fixture pack can contain a rule deliberately designed to be INDETERMINATE, one whose quote
  disagrees with its bound, one requiring an observation nothing produces. Real codes contain
  none of these on demand.
- Published research rule sets, as shape references.

**Who ratifies** is therefore not answered now and does not need to be. It is answered before
real content is loaded, with a measured number in hand: how long reviewing one rule actually
takes. That number comes out of the harness, which is why it was the wrong question to ask
first.

## Expected result
O2's harness is complete and measurable — Gate 1's numbers (records per day, fraction surviving
unedited, fraction failing the quote linter) become obtainable the day a ratifier exists.

## Reopens if
Not applicable to the harness. The open half closes when the stakeholder names someone.

## Consequences accepted
Real coverage arrives late, so the first genuine "N of M provisions" number arrives late with
it. Accepted, and correct: the number is only meaningful once the machine producing it is
proven, and a pipeline validated against synthetic packs designed to break it is better proven
than one validated against whichever real clauses happened to be easy.

**Correction to an earlier claim in this record:** the ratifier was described as the top
schedule risk and the critical path. That was wrong. It gates shipping real findings, not
building the system, and the stakeholder has now sequenced it last deliberately.

## A note on wording
The stakeholder's phrasing — *"the building codes will be used in run time"* — is read here as:
the compiled packs are what the engine loads and runs against at check time. It is **not** read
as translating regulatory text during a run, which would put an inference client in the request
path and violate I1 and `prd.md` §8's artifact-mediation requirement outright. Flagged for
confirmation; the framework assumes the former.
