# Decomposition

How a one-sentence goal becomes tasks a subagent can finish in one session, without anyone
holding the whole system in their head at once.

## The five levels

```
L0  Goal          One sentence. Never changes.
L1  Outcome       A state of the world the stakeholder can judge. 5–10 exist.
L2  Capability    A coherent observable ability. 3–8 per outcome.
L3  Slice         One vertical behaviour crossing every layer, with fixtures. 3–10 per capability.
L4  Task          One subagent session. 1–5 per slice.
```

Each level answers a different question, and mixing them is the usual way a plan becomes
useless:

| Level | Question | Judged by | Wrong if it mentions |
| --- | --- | --- | --- |
| L0 | Why does this exist | — | anything technical |
| L1 | What state of the world are we buying | **Stakeholder** | modules, libraries |
| L2 | What can the system then do | Lead | files, functions |
| L3 | What behaviour proves it | Lead | line-level design |
| L4 | What does one agent do | Lead | anything outside its file list |

## The two rules that make this work

### Rule 1 — breadth before depth

**Expand one level at a time, across the whole level, before expanding any branch of it.**

Enumerate every L1 outcome before decomposing any of them. Enumerate every L2 capability of
the chosen outcome before writing any L3 slice.

The failure this prevents is the natural one: the first interesting branch gets decomposed
to L4 while its siblings are still a phrase, the plan acquires false precision on one side
and nothing on the other, and the real dependency — which sits in an unexpanded sibling — is
discovered after the code exists.

A level is settled when **every** node at that level is written down, and the stakeholder has
chosen among them where the choice is theirs.

### Rule 2 — prerequisite order is absolute

**No part is started while anything it depends on is unbuilt.**

Not "started in parallel with a stub". Not "built against a mock we will replace". If a slice
needs a real derived model and derivation does not exist, that slice does not start.

`docs/roadmap/dependency-order.md` is the graph, and the graph is the schedule. There is no
separate schedule. Every task spec names its prerequisites and the evidence each is complete
(`docs/process/task-spec.md`), and a subagent whose prerequisite evidence is missing stops
without starting.

This rule costs parallelism. It buys the thing that matters more: nothing is built against an
assumption about an unbuilt neighbour, so no work is invalidated when the neighbour turns out
different. In a codebase generated by agents that cannot notice a drifted assumption, this is
not caution — it is the only version that converges.

## Subagent-readiness

L4 is reached when all five hold. Until then, decompose further.

1. **Fits one session with room to spare.** Roughly one module, under ~400 lines of new code.
2. **Contracts are written and typed.** Inputs, outputs, errors. The agent implements a signature it did not invent.
3. **Context list is exhaustive.** The agent reads those files and no others. If it needs a sixth file, the task was mis-specified.
4. **Acceptance is a command.** An exit code, not a description. "Works correctly" is not acceptance.
5. **Prerequisites are complete, with evidence.**

If a task cannot be made to satisfy (3), that is usually the real signal: the module boundary
is wrong, and the fix is in `docs/ddd/03-bounded-contexts.md`, not in the task.

## Where the stakeholder enters

Exactly once per level, and only at L1.

The Lead presents the L1 outcomes with their dependency order and asks which to pursue and
what "worth it" looks like. The stakeholder answers in outcomes. L2 and below are the Lead's,
and a stakeholder question about an L2-or-lower matter is answered rather than asked.

The stakeholder is asked again only when an outcome is reached, or when evidence contradicts
a `prd.md` §12 decision at its printed Reopens condition.

## Re-decomposition

A slice that turns out wrong is **re-decomposed, not patched**. The plan is cheap; the code
is not. Discovering at L3 that a capability was mis-shaped means going back to L2, not adding
a task to compensate.

Every re-decomposition that changed a decision produces a decision record. Every one that did
not is silent — the plan is allowed to be wrong; the log is not allowed to be incomplete.
