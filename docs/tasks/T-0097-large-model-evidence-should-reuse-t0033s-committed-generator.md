# T-0097 — T-0062's large-model proofs used an uncommitted script instead of T-0033's own

**Phase:** 3   **Status:** open
**Touches invariants:** none — a reproducibility gap in a real-path proof, not a code
defect. Low priority: the evidence it supports is already independently verified.

## Why

Found by T-0062's review. Proofs 1 and 2 in T-0062's evidence used a 340,000-door IFC model
generated by "a one-off script mirroring `make_fixtures.py`'s own method just at scale,"
never committed. `scripts/generate_large_ifc_model.py` already exists, committed by T-0033
for exactly this purpose — growing a real model to a target size rather than synthesising
one from scratch — and CLAUDE.md's own rule is "inherit before writing" plus "fixtures are
… a script that generates them," not a throwaway. The reviewer also noted the evidence's
perfectly-even three-way split (113334/113333/113333 pass/fail/indeterminate) is the
signature of a round-robin generator, distinguishable from what T-0033's own script
produces — worth confirming either script produces equivalent real coverage, or that the
difference doesn't matter for what these proofs demonstrate (timing and claim-count
behaviour, not check-result distribution).

## Scope

- If T-0062's evidence needs to be reproduced again for any reason (a future regression,
  a review re-verification), use `scripts/generate_large_ifc_model.py` rather than writing
  a new one-off generator.
- Not asking for T-0062's already-accepted evidence to be re-captured retroactively — this
  is guidance for the next time this class of proof is needed, recorded so the throwaway
  script isn't reached for again out of habit.

## How to prove it ran

No code change necessarily required. If `generate_large_ifc_model.py` cannot in fact serve
this purpose (e.g. it lacks a needed parameter), extend it rather than writing a parallel
script, and say what was added.
